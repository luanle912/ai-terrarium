# Bầu trời 8 đảo (GĐ3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Làm trọn khối GĐ3 ở §0 của spec: hub chứa tối đa 8 đảo, mỗi đảo một `slot` cố định, "Toàn cảnh" là 8 chỗ cố
định lấy người xem làm tâm (không kéo, không zoom, không bản đồ nhỏ), bấm đảo thì mây khép rồi mở ra màn một đảo vẽ đầy
đủ, "Của tôi" mở đảo của mình theo cùng cách.

**Architecture:**
- Hub: DB nâng lên **v3** (`islands.slot`, chỉ mục `UNIQUE` một phần, `device_codes.deny_reason`). Kiểm đủ chỗ và tạo
  đảo nằm trong một transaction của `hub/db.js` (`claimIsland`). Sự kiện `world` lấy danh sách đảo **từ DB** (mọi đảo có
  slot) và trộn trạng thái RAM của `hub/world.js` vào, kèm `slot` và `capacity`.
- `claude-office.html` vẫn một file. `world-logic` bỏ camera tự do (vòng xoắn, `fitAll`, `focusOn`, `camStep`, LOD
  `mid`/`thumb`) và thêm ba nhóm hàm thuần: bố cục 8 chỗ quanh người xem (`skyLayout`), dò trúng (`skyHit`) và dòng thời
  gian mây (`cloudPhase`, `cloudBands`, `canNavigate`). `world-view` vẽ "Toàn cảnh" bằng một hàm vẽ đảo đơn giản mới,
  màn một đảo bằng đường vẽ `full` hiện có, và một lớp mây trên canvas.
- `CameraLogic` (kéo, zoom của trang local) **không đổi**. Trang local giống từng pixel.

**Tech Stack:** Node ≥ 22.13 cho hub (`node:sqlite`), Node ≥ 18 cho server local và publisher; `node:test`, `node:vm`;
React 18 UMD, Canvas 2D.

**Spec:** `docs/specs/2026-11-04-multi-island-design.md`. Phạm vi và quyết định của anh Kiet ngày 2026-11-05 ở §0 (khối
GĐ3, gồm cả quyết định 2 đã đổi sang bố cục lấy người xem làm tâm); khối này ghi đè §12.2 và §12.3 ở mọi chỗ còn nói tới
vòng xoắn, camera, bản đồ nhỏ hay LOD bốn mức.

4. **Bấm nhanh hai lần trong lúc chuyển cảnh.** Bấm đảo A rồi đảo B (hay Esc, hay nút "Toàn cảnh") trước 850ms: lệnh thứ

### Task 1 [hub]: DB v3: `slot`, `MAX_ISLANDS`, `claimIsland`

**Files:**
- Modify: `hub/db.js`
- Test: `tests/hub-db-migrate.test.mjs`, `tests/hub-base.test.mjs` (nếu đụng `upsertIsland`)

**Interfaces:**
- Produces (export từ `hub/db.js`, và trên đối tượng `db` của `openDb(path)`):
  - `SCHEMA_VERSION = 3`, `MAX_ISLANDS = 8`. `user_version > 3` thì throw `Error('hub.sqlite is newer than this hub')`.
  - `migrate(raw, now)`: giữ khối `version < 2` nguyên văn, thêm khối `version < 3`, vẫn **một** transaction:
    ```sql
    ALTER TABLE islands ADD COLUMN slot INTEGER CHECK(slot BETWEEN 0 AND 7);
    ALTER TABLE device_codes ADD COLUMN deny_reason TEXT;
    WITH r AS (SELECT id, ROW_NUMBER() OVER (ORDER BY created_at, id) - 1 AS n FROM islands)
      UPDATE islands SET slot = (SELECT n FROM r WHERE r.id = islands.id)
      WHERE id IN (SELECT id FROM r WHERE n < 8);
    CREATE UNIQUE INDEX islands_slot ON islands(slot) WHERE slot IS NOT NULL;
    ```
    Comment đầu file và comment `migrate` nói rõ 0 → 2 → 3.
  - `claimIsland({id, userId, name, color, now}) => {island, created: boolean} | {full: true}` trong
    `BEGIN IMMEDIATE … COMMIT`:
    - user đã có đảo → `{island, created: false}` (kể cả khi hub đủ, kể cả khi đảo đó `slot = NULL`);
    - `SELECT COUNT(*) FROM islands` ≥ `MAX_ISLANDS` (đếm cả đảo ẩn) → `{full: true}`, không ghi gì;
    - còn lại: slot = số nhỏ nhất trong 0–7 chưa dùng, `INSERT`, → `{island, created: true}`.
    - Lỗi `UNIQUE` trên slot (không xảy ra trong một tiến trình, chỉ là chốt chặn) → ROLLBACK và trả `{full: true}`.
  - `upsertIsland(...)` giữ chữ ký cũ cho test cũ: chưa có đảo thì đi qua `claimIsland` (đầy thì throw
    `Error('hub full')`), đã có thì đổi `name`, `color` như cũ. Code hub không gọi nó nữa.
  - `deleteIslandByUser(userId) => boolean`: cùng transaction, sau khi xoá, nếu đảo bị xoá có slot `s` và còn đảo
    `slot IS NULL` thì đảo cũ nhất trong số đó (`created_at`, rồi `id`) nhận `slot = s`.
  - `listSlottedIslands() => Island[]`: `WHERE slot IS NOT NULL ORDER BY slot`.
  - `islandCount() => number` (đếm cả đảo ẩn).
  - `denyDeviceCode(codeHash, reason = null) => boolean`: đặt `denied = 1, deny_reason = ?`.

- [ ] **Step 1: Viết test hỏng** trong `tests/hub-db-migrate.test.mjs`. Thêm hằng `V2_STEPS` chép nguyên khối SQL
  `version < 2` hiện tại để dựng DB v2 (GĐ1 `SCHEMA` + `V2_STEPS` + `PRAGMA user_version = 2`).
  - `a v2 database with 10 islands gets slots by creation order`: 10 user, 10 đảo, hai đảo cùng `created_at` (thứ tự
    theo `id`). Sau `openDb`: `user_version` = 3; 8 đảo đầu slot 0–7 đúng thứ tự; 2 đảo sau `slot` NULL; mọi cột khác
    giữ nguyên; `PRAGMA index_list(islands)` có `islands_slot`; `device_codes` có cột `deny_reason`.
  - Sửa `a GĐ1 database is upgraded in place` và `a fresh database starts at version …` để dùng `SCHEMA_VERSION` (3);
    `a newer database is refused` đặt `user_version = 4`; `opening twice is a no-op` giữ nguyên slot.
  - `claimIsland gives the smallest free slot`: 3 đảo → slot 0, 1, 2.
  - `claimIsland refuses a ninth island`: 8 đảo → `{full: true}`, `islandCount()` vẫn 8.
  - `a user with an island gets it back on a full hub`: `created: false`, cùng `id`, cùng slot.
  - `a freed slot is reused`: 8 đảo, `deleteIslandByUser` của đảo slot 3 → `claimIsland` mới nhận slot 3; slot các đảo
    khác không đổi.
  - `a freed slot goes to the oldest hidden island first`: DB 10 đảo (từ ca nâng cấp) → xoá đảo slot 5 → đảo ẩn cũ nhất
    nhận 5, đảo ẩn còn lại vẫn NULL, `islandCount()` = 9, `claimIsland` người mới → `{full: true}`.
  - `the slot index rejects a duplicate`: `UPDATE islands SET slot = 0` cho đảo slot 1 → throw `/UNIQUE/`.
  - `the slot check rejects 8`: `UPDATE … SET slot = 8` → throw `/CHECK/`.
  - `listSlottedIslands is ordered by slot and skips hidden ones`.
  - `denyDeviceCode keeps the reason`: `'hub_full'` lưu được; gọi không lý do → `deny_reason` NULL.
